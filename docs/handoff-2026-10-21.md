## Setting up the new machine

1. **Clone and check out `eplb-evaluation`**. Everything up to this handoff is
   on that branch and in the PR opened with this note.
2. **SSH to the node.** `nrun`/`npull` expect a `Host ascend` entry in
   `~/.ssh/config` (copy the block from the old machine: HostName, `User dylan`,
   `ControlMaster auto`, `ControlPath ~/.ssh/cm-%r@%h:%p`, `ControlPersist 10m`,
   `ServerAliveInterval 30`) and the key that goes with it. Check with
   `./nrun 'npu-smi info'`. The address is not in this repo because the repo is
   public.
3. **The local analysis venv.** Do **not** bootstrap it with a plain `uv run` or
   `uv sync` at the repo root. That resolves the full project, vllm-ascend,
   torch-npu, triton-ascend and the rest, which CLAUDE.md forbids locally (on
   2026-10-21 it started downloading them and stopped only because the disk was
   full). What the old machine had: Python 3.12, the results package editable,
   plus numpy, pandas and matplotlib:

   ```bash
   uv venv --python 3.12
   uv pip install -e ./packages/moe-reliability-results matplotlib pandas
   .venv/bin/python scripts/<script>.py ...      # or: uv run --no-sync python ...
   ```

4. **`results/`** (4.7 GB here, gitignored). The node holds the originals, so
   `./npull` brings them back. `npull` skips `activations/` and `traces/`, so
   copy any single capture or trace you need with rsync rather than `npull -a`,
   which pulls tens of GB. The newest run is
   `20261020-064000_..._eplb-standing`. The node could not be reached from the
   old machine on 2026-10-21 (no agent for the key), so nothing newer was
   checked for. List the node's `results/` before treating anything as unrun.
5. **The vllm-ascend clone** (`~/src/vllm-ascend` on the old machine). Both fix
   branches are pushed to the fork, so nothing local is lost. Re-create it with:

   ```bash
   git clone https://github.com/deveringham/vllm-ascend.git ~/src/vllm-ascend
   cd ~/src/vllm-ascend
   git remote add upstream https://github.com/vllm-project/vllm-ascend.git
   git fetch upstream
   git switch fix-eplb-record-mode; git switch fix-eplb-honour-changed
   ```

   `docs/pr_drafts.md` says why rebases go onto the *fork's* `main` (a push is
   refused without the `workflow` token scope otherwise), and also covers DCO
   and the CI-enforced title tags.

## Computed, not yet written up: Mixtral's prompt and decode routing

`natural-decode-mixtral` (2026-10-16, 5999 unbiased requests, 100 generated
tokens, level 0 only) is the Mixtral counterpart of B3 in
`docs/detection-findings.md`. `scripts/decode_signal.py` on it gives:

| | prompt | decode | both | busiest rank agrees | share correlation |
|---|---|---|---|---|---|
| Mixtral, 32 layers | 1.2218x | 1.0851x | 1.1622x | 13 of 32 (chance 8) | +0.366 |
| DeepSeek, 26 layers (B3 capture) | 1.0797x | 1.0553x | 1.0514x | 10 of 26 (chance 6.5) | +0.085 |

On Mixtral the pooled reading lies **between** the two sources. That is
dilution, not the cancellation DeepSeek shows, where the pooled reading falls
below both. The sources are also far more alike (+0.37 against +0.09), and
prompt routing is much more concentrated than decode. So "pooling hides both" in
CLAUDE.md is a DeepSeek result. On Mixtral pooling hides the prompt skew, which
is the one that costs, behind a lower decode floor. Detection at a 1% alarm set
on each source's own level 0 is 0.01 everywhere, as it should be with nothing
injected. This belongs in B3 and in the CLAUDE.md bullet before anyone quotes
"cancellation" as general.
